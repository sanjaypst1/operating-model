# COMPASS Research Register

**Access date for this build:** 2026-09-20

## Method

1. Review publicly accessible materials on product operating models, Team Topologies, lean portfolio management, Flight Levels concepts, Agile ways of working, DORA/software delivery performance, GDS service standards, Scrum accountabilities, and related practices.
2. Translate principles into an **original COMPASS model** (do not copy proprietary diagrams or protected frameworks wholesale).
3. Label each claim as **evidence**, **interpretation**, or **recommendation**.
4. Record title, publisher, publication date (as available), access date, URL, what the source supports, and limitations.

## Distinction

| Label | Meaning |
|-------|---------|
| Evidence | Grounded in a cited public source |
| Interpretation | COMPASS synthesis across sources |
| Recommendation | Suggested practice for COMPASS adoption |

## Gaps / validation required

- Organisation-specific success rates: **not invented**
- Proprietary maturity benchmarks behind paywalls: **source validation required** if needed later
- Vendor case studies: treat as illustrative unless independently verified; fictional UI examples must be labelled

## Fictional examples policy

Any narrative examples in the product UI that are not drawn from cited public cases must be labelled **fictional**.
